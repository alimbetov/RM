## 1. Architecture and non-goals
Reuse authorized L0–L3 reads, DQR quality, existing IAM and file infrastructure. Report renderer consumes typed results, never recomputes business metrics. Separate report identity/metadata, optional immutable large tabular snapshot payload, and Excel/PDF artifacts. No duplicate warehouse, separate database per tenant, or mandatory persistence of every report row. Small reports may persist only immutable artifact plus evidence manifest if reproducibility requirements are met. Existing L0–L3 keys, generation lifecycle and source identities are unchanged.

## 2. Optional long-retention archive candidate (not delivery staging)
Report metadata and jobs: ordinary PostgreSQL tables, tenant-leading indexes. Large new snapshot-row table: design compatible with monthly RANGE(snapshot_month) and optional HASH(tenant_id) subpartitions; start by benchmarking unpartitioned, RANGE only and RANGE+HASH 4/8/16. Choose the simplest passing configuration before first production migration. snapshot_month is immutable first day of UTC creation month, NOT reporting business period, so a multi-year report is located in one partition and expiry does not depend on historical metric dates. Business periods remain separate calendar-versioned half-open bounds. Query by tenant, snapshot_month, snapshot_id; never derive partition routing from requested period. A hash bucket is not a security boundary. No LIST per tenant by default. Large shared partitions require per-tenant quotas and fair scheduling, not claims of physical isolation.

## 3. Optional archive logical model (not executable migration; conceptual aliases only)
report_request: PK(tenant_id,request_id); UNIQUE(tenant_id,idempotency_key); canonical request digest, actor, report type, template/method/presentation version, normalized filters, calendar version, period bounds, status. Same idempotency key with different digest is conflict.
report_snapshot: PK(tenant_id,snapshot_id); UNIQUE(tenant_id,snapshot_id,snapshot_month); FK(tenant_id,request_id); snapshot_month DATE NOT NULL; creation timestamp UTC; source revision, as_of, per-window generation/proof/quality evidence, manifest digest, row count. Enforce month equals UTC creation month by check and immutability. One request may have multiple explicitly versioned snapshots only if policy permits; retries reuse reserved identity. New revision creates new immutable snapshot.
report_snapshot_row (optional): PK(tenant_id,snapshot_month,snapshot_id,row_no); FK(tenant_id,snapshot_id,snapshot_month) -> report_snapshot; row_no positive; typed payload and schema version; RANGE(snapshot_month), optionally subpartition HASH(tenant_id). All unique constraints include every partition key. Parent metadata anchors cross-month identity; no global uniqueness claim for row table alone. Store decimal values losslessly, explicit NULL and quality, dimension identifiers and units/currency. No PII unless report contract expressly authorizes it.
report_artifact: PK(tenant_id,artifact_id); FK(tenant_id,snapshot_id); UNIQUE(tenant_id,snapshot_id,format,renderer_version); object key, digest, size, media type, status, created/expiry; immutable READY object. Metadata is authoritative; object key is not authorization.
Indexes: report_request(tenant_id,created_at DESC,request_id); report_snapshot(tenant_id,request_id); row PK supports scoped ordered streaming; artifact unique supports lookup. Add secondary period/type indexes only after query evidence. Exact DDL, status enums and retention values require approval; names are logical and must be reconciled with existing report TЗ.

## 4. Source and mathematical contract
All report metrics include metric/method version, grain, dimensions, currency/unit, calendar version, actual_as_of, source revision, route, quality and proof where applicable. A 24-month dataset requires one admitted bounded authorized snapshot across its entire metric/scope plan; repeated calls to the current 12-anchor/3-metric API do not satisfy it. An alternative pinned source must retain all exact immutable rows and versioned dependencies, not merely a revision number or active-generation ID. Calendar, dimension mapping, methods, coverage and actual authorized scope are part of the manifest. RR provides a consistent visible snapshot, not proof that every business event before a timestamp has arrived. Preserve event cutoff, observation time and completeness evidence separately. No historical-as-of claim from current visibility alone.

Dataset READY means complete immutable serialization only; analytical quality, eligibility for a conclusion and report publication are separate fields/gates. Current AuthorizedAnalyticalReadService returns PARTIAL/MISSING even on CURRENT_SOURCE_PARITY. Never upgrade these in staging/renderer; qualified zero needs independent owner completeness evidence. Explicitly permitted descriptive partial output carries its quality and warnings; completeness-dependent blocks remain unavailable. Distinct orders/SKUs/lines use exact union membership at target grain, not sums of group counts. Use ratio-of-sums or weighted averages only for matched populations, basis, currency/unit and periods; denominator zero yields an explicit undefined result, not zero/infinity. Cumulative intraday observations replace the earlier cutoff for that day and are not summed; a correction can reduce a later cumulative value. Statistical windows preserve missing periods, sample/population convention and method eligibility. Round only for presentation; chart/table values share the same qualified payload, with any display-rounding discrepancy labelled. Late facts create a new immutable dataset/report version; old bytes/digest remain unchanged and supersession is separate audited metadata. [Independent mathematical vectors](intelligent-commerce/RM-ARS-R1-DESIGN-QUALIFICATION.md#4-mathematical-reference-vectors) specify the expected results.

## 5. Security and publication
VerifiedActor + current tenant RBAC and report-specific underlying metric/PII permissions for request, execution and download; dedicated least-privilege service identity for background execution, not fabricated human principal. Tenant included in all keys, joins, job payloads, caches, object paths and audit. Revalidate requester authorization before publish and download; revoked membership fails closed. Do not treat tenant prefix or partition pruning as access control. Deny direct child-table access to application roles; consider RLS only with real role, pool reset, owner/bypass and partition direct-access qualification. Object keys server-generated, private objects, short-lived authorized download or authenticated streaming; signed URL revocation window explicit. No public bucket. Spreadsheet formula injection protection for untrusted text. Encryption and lifecycle follow existing platform standards.

Publication: reserve request and snapshot identity transactionally; write bounded snapshot; verify row count, ordered canonical digest and evidence; render/upload to immutable temporary/staged key; verify object digest; commit the single publication receipt/artifact references with consumer fencing and PUBLISHED_PENDING_ACK; cleanup orphan objects asynchronously using existing infrastructure with a file/reference state fence shared with publication, so GC cannot delete a newly committed referenced artifact. PostgreSQL and object store are not one ACID transaction. Crash/retry must not publish incomplete artifact, overwrite prior READY, or duplicate logical publication. Explicit state/transition contract in implementation design.

## 6. Optional archive lifecycle and operation (not daily staging)
Retention separated for canonical source, projections, snapshot rows, artifact and audit metadata. No automatic deletion until tenant policy, legal hold and references checked. Month partition detach/drop only when ALL tenants' rows in it eligible and no held data; otherwise scoped row deletion or keep partition. Precreate next months, alert on missing partition, fail closed; no silent unbounded default partition. Restores and replays preserve identity and digest; qualify backup/restore and tenant-specific export/delete. Monitor per-tenant bytes, row count, report concurrency and latency, queue age, partition count, skew, autovacuum, index size, WAL, lock duration, pool usage. Prefer streaming bounded batches to memory-heavy rendering.

## 7. Optional archive capacity and qualification
Illustrative rows = tenants * reports per tenant per month * rows per report * retained months; not all analytical cells need copying. For 1000 tenants, 10 reports/month, 1000 rows/report, 24 months: 240M rows if every report persists rows; RANGE 24 leaves, RANGE+8 HASH 192 leaves. Actual size = measured table + indexes + TOAST + artifacts, plus separately measured WAL/backup. Hash balance depends on tenant size; large tenant remains in one bucket per month.
Compare same fixture, same workload and PostgreSQL version: 10/100/1000 tenants, skewed hot tenant, 1/12/24 months, concurrent generation/download and OLTP; measure p50/p95/p99 per operation, planning/execution, buffers, partition pruning, temp spills, writes/WAL, vacuum, storage, queue age. Reuse Q2-FINAL P5 matched OFF/ON business thresholds p95<=10%, p99<=20%, zero deadlocks/pool timeouts; report-specific SLA and resource budgets require approval. Do not infer speedup from partition count. Prefer unpartitioned or RANGE-only if targets met. Admission requires exact parity against qualified analytical source; zero cross-tenant reads/writes/downloads, duplicate publish, missing rows, mismatched hashes, unsafe deletion; crash recovery across pods; boundary month/DST, late data, restore, revocation, direct partition access and multi-year report tests. Exact-SHA required for implementation. Design only; no runtime evidence claimed.

### 9.2 SQL model and constraints
Proposed reporting schema; reuse existing registry/job/file owner tables if equivalent. Minimal persistent roles:
- int_report_instance PK(tenant_id,instance_id), UNIQUE(tenant_id,idempotency_key), immutable request/actual scope digest at admission, final evidence passport set exactly once at successful publication, current lifecycle, job reference; mutable visibility version/ACL separate from content. Tenant/workspace FK and all cross-entity FK tenant-scoped.
- int_report_visibility keyed by tenant/instance and approved audience grant identity; grant version/audit, default private, revocation independently mutable.
- Durable dataset attempt metadata (embed in existing job metadata only if equivalent; otherwise minimal int_report_dataset_attempt): PK(tenant_id,dataset_id), UNIQUE(tenant_id,dataset_id,staging_date), immutable UTC allocated date, source manifest and schema version, monotonic build token, build state, expected and observed row count/digest, lifecycle/recovery deadlines. dataset_id identifies one extraction attempt, not the logical report request. Lost source snapshot before complete durable validation requires a new dataset_id; never append a fresh read to old partial rows. Resume a frozen complete dataset only by verifying its retained bytes/source manifest. Execution takeover of a READY consumer changes consumer token, not dataset content/build identity.
- Durable consumer identity PK(tenant_id,instance_id,consumer_id), FK to instance and to (tenant_id,dataset_id,staging_date); immutable links, monotonic consumer token, state, lease, immutable publication receipt/time and terminal disposition/time. Build token and consumer token cannot be interchanged. Reuse only identical scope/evidence with separate access checks. Register consumer under shared date fence before any render; rebuild registers a new consumer identity and preserves the old immutable link/disposition; no registration after retirement. Keep pin identities, expiry, token and hold/recovery flags durable. Never infer all consumers from current staging rows; no FK from durable history to disposable rows. Retain dataset identity metadata until all durable references allow its removal.
- int_report_dataset: daily RANGE(staging_date), PK(staging_date,tenant_id,dataset_id,row_key), FK(tenant_id,dataset_id,staging_date) to durable attempt identity; row_key deterministic total order (e.g. fixed-width canonical ordinal), typed decimal NUMERIC, explicit quality, nullable value per admitted metric contract, unit/currency, dimension and period references. No DEFAULT, initially no HASH. All row access binds tenant/date/dataset. PK already supports ordered scan with equality on date/tenant/dataset; add tenant-first local secondary index only if EXPLAIN proves benefit. All constraints/index grants verified on each child. Separate canonical digest format version; do not hash unstable Java toString or rounded Excel cells.
- Optional artifact mapping only if existing File Service binding cannot express tenant/instance/format/version identity. Unique (tenant_id,instance_id,format) for a report instance with immutable template/renderer versions; deliberate regeneration makes a new instance/version, not an additional READY artifact slot on the same instance. Store immutable file digest, no raw public URL. Publication references already registered consumers; do not insert new dataset/consumer links during publication. No direct child privileges for app; parent ACL not a substitute for tenant predicates.

Lifecycle UPDATEs use tenant + identity + expected state + matching token and verify exactly one affected row; a retry may return an already committed result only after matching its immutable digest/receipt and current authorization. CHECK constraints enforce nonnegative counts, required READY fields, allowed state values, and publication/terminal timestamps consistent with state. Cross-row immutability/fencing requires an admitted repository or narrow DB routine/trigger; illustrative DDL below does not implement it. FK and trigger lock acquisition must be included in the lock audit. Durable identity keys are immutable; no cascading delete. No external caller supplies raw SQL identifiers, object keys or another tenant's handle.

Candidate daily DDL (illustration only):

Not complete executable migration: remaining typed schema, quality checks, grants, immutability guards and job integration required. Reuse existing DataQuality {READY,PARTIAL,MISSING,STALE,NOT_MEASURABLE}; completeness is an evidence property, not a new COMPLETE enum. Dataset lifecycle READY is a different type from analytical DataQuality.READY. If attempt metadata reused rather than separate table, FK target must preserve equivalent unique identity. No archive by default.

Canonical dataset encoding v1 (design contract, not a replacement metric engine): SHA-256 over ASCII `RM-ARS-DATASET-1` followed by LF, then framed canonical header JSON, then one framed canonical row JSON per ascending contiguous row_key 1..N, then framed ASCII decimal N. Frame is ASCII byte-length + `:` + exact bytes; no separator ambiguity. Header contains exactly schema, tenant, dataset, scope_sha256 and source_manifest_sha256. JSON uses UTF-8, lexicographic ASCII object-key order, no whitespace/BOM, no numeric JSON tokens: integers and decimals are canonical strings; null is JSON null. Canonical IDs/codes/digests are ASCII; UUID lowercase, digest lowercase hex; no user labels or localized strings enter these bytes. Scope and source-manifest bytes have their own registered version and immutable digests, not timestamps alone.

Row is an ordered array `[row_key,metric_code,method_version,from_inclusive,until_exclusive,dimensions,unit,currency,value,quality,reason]`. Timestamps are UTC with six fractional digits and `Z`, explicit half-open bounds; reject excess source precision unless an admitted conversion preserves meaning. Dimensions are sorted unique `[kind,id,mapping_version]` triples (ASCII lexical order); absent currency/value/reason is JSON null. Integers have no leading zeros; decimals are exact plain notation without trailing fractional zeros, with negative zero canonicalized to `0`; NaN/infinity rejected. `1000` remains `1000`. Schema changes require new encoding version. Staging date/build/consumer tokens and mutable ACL/state are outside payload digest; allocated dataset identity and source/scope are bound in header. Zero-row serialization is defined, but business empty/zero eligibility remains independent. [Executable golden vector M12](intelligent-commerce/qualification/rm_ars_r1_reference_oracles.py) gives 484 bytes and SHA-256 `f54eae406408e614c77b222932179052d01819dbaa7757d2e0f2470601293995`; Java/SQL/renderer must reproduce it before implementation qualification.

### 9.3 Transaction and lock graph
All lifecycle/publication transactions use READ COMMITTED with bounded timeouts. Acquire the relevant locks first, then read fresh DB time and current state; transaction_timestamp() or a pre-wait lease check is insufficient for expiry. Token and lease are checked again in the guarded mutation. No fence upgrade from shared to exclusive in one transaction.

| Transaction | Required order and commit boundary |
|---|---|
| T0 request | IAM actor/workspace -> complete owner scope -> instance/visibility; canonical idempotent intent, commit |
| T1 claim | Existing admitted queue claim, commit before IAM or partition fence; analytical NIGHT/INTRADAY jobs are not an already implemented report queue |
| T2 allocate/register | Shared date fence -> dataset attempt -> consumer/pin rows (new consumer REGISTERED); current DB UTC date for new allocation; existing immutable date for registered consumers; commit before extraction |
| T3 extract | No active report transaction. One bounded authorized analytical RR snapshot; independently derive expected canonical row count/digest from that extraction. Close source transaction before rendering/upload. Memory/spool/streaming strategy needs an explicit bounded budget; snapshot loss never resumes by rereading only the missing pages |
| T4 append | Shared date fence -> BUILDING attempt row; post-lock DB time/build token; append bounded deterministic batch; identical canonical duplicate is idempotent, mismatched duplicate aborts, never ON CONFLICT DO NOTHING alone |
| T5a freeze | Same fence/order; BUILDING -> VALIDATING and immutable expected manifest; freeze all content writes and acquire validation pin; commit |
| T5b validate | Bounded keyset reads under short shared-fence transactions/live validation pin. Frozen bytes permit deterministic count/digest without one long write transaction. Compare observed bytes against independently recorded expected manifest; page count alone is not completeness |
| T5c READY | Shared date fence -> attempt; compare token, frozen version, validation evidence, live pin and all expected/observed counts/digests; VALIDATING -> READY atomically; content remains immutable |
| T6 render | Register consumer first; REGISTERED -> ACTIVE only with READY handle/pin; acquire/renew/read/release pin with shared date fence -> attempt -> consumer/pin; verify READY manifest and consumer token every page; no DB transaction during conversion/upload |
| T7 files | Existing admitted IAM -> report owner -> file order; private attempt-specific immutable file identities; scan/upload outside report/partition transaction |
| T8 publish | Current IAM/requester/owner scope -> instance/visibility -> durable consumer row -> file rows sorted by ID. Recheck live consumer token/lease, READY handle, required formats and current CLEAN/AVAILABLE/owner/digest/storage state. While holding the instance row, require it unpublished or an exact idempotent match to this consumer/receipt; atomically set its single publication receipt/artifacts and CAS consumer ACTIVE -> PUBLISHED_PENDING_ACK. A competing different consumer cannot publish a second outcome; its unpublished resources are terminalized separately through T9. No partition fence, source query or attempt-row lock here |
| T9 ACK/recovery | Shared date fence -> attempt -> consumer; verify immutable publication receipt from committed durable metadata without report/file row locks; PUBLISHED_PENDING_ACK -> PUBLISHED_ACK. Preserve original published_at, never recovery time. Until ACK, cleanup blocked |
| T9 abandon | Shared date fence -> attempt -> consumer; CAS only unpublished REGISTERED/ACTIVE to ABANDONED with admitted reason/deadline and invalidated token; cannot overwrite PUBLISHED_PENDING_ACK/PUBLISHED_ACK, cannot run from lease expiry alone |
| T10 cleanup | Bounded maintenance coordination -> exclusive date fence -> all attempts/consumers/pins in canonical order -> verified child DDL; atomically persist retirement and DROP. No IAM/file/network or report-instance row locks; parent table lock timeout rolls back entire operation |

Publication and abandonment serialize on the SAME durable consumer row. If publication wins, abandonment observes PUBLISHED_PENDING_ACK and cannot erase success; if abandonment wins, T8 fails its CAS. New consumer/pin registration is blocked by exclusive date fence; publication cannot create a phantom consumer. All state/lease/hold changes use the same coordination; read fresh eligibility after lock waits. FK/trigger side effects must not introduce T8 consumer -> attempt lock or report/file -> lifecycle fence edges. Use immutable identity keys and compatible NO KEY UPDATE lifecycle locks where needed to avoid FK KEY SHARE inversions; verify actual SQL, not just this abstract order. No path acquires IAM after a lifecycle fence or enters lifecycle operations while holding report/file locks. [Full graph and failure schedules](intelligent-commerce/RM-ARS-R1-DESIGN-QUALIFICATION.md#5-transactional-qualification) remain mandatory real PostgreSQL evidence.

### 9.4 Multi-pod lifecycle
Use transaction advisory fence with reserved parent namespace and stable integer day key (days since epoch), same key for create/allocate/register/pin/write/seal/hold/cleanup; shared for access, exclusive for create/drop. Lock is coordination, not authorization. Verify namespace collisions and owner grants. DB-derived UTC date, trusted deterministic child name. Narrow privileged routine verifies parent OID, bounds, indexes, grants and tombstone; no IF NOT EXISTS-only success. Fixed bounded lookahead current + 2 days; precreated future child does not admit future-date allocation. At UTC midnight date becomes SEALED for allocations but existing valid attempts/pins can finish. Never recreate RETIRED dates; unexpected missing active child fails closed and enters recovery. No unbounded historical catch-up creation.

An expired lease blocks further worker mutations but does not itself authorize drop. Takeover increases the corresponding build/consumer token under its row lock; old token cannot renew/read/write/seal/publish/ACK/abandon. A live page read holds shared fence to commit; renewal after expiry cannot resurrect that token. If source snapshot is lost while BUILDING, abandon that dataset and start a new dataset_id/current date. READY bytes can be consumed by a new authorized execution without changing the source manifest.
