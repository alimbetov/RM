## 1. Single tenant ownership and controlled visibility (P0)
Each job, request, payload, report instance, evidence, file, cache and publication belongs to exactly one tenant. Tenant admin/authorized delegated manager configures report audience and allowed scope using existing membership/roles/employee IDs and owner scope permissions. Default private (author or designated owner/admin only if independently authorized); explicit audience grants may include ALL_AUTHORIZED, ROLE, EMPLOYEE; branch/warehouse restrictions are scope filters, never new permissions or roles. Tenant admin is not a bypass of domain permission, warehouse assignment, PII, or file owner rules. No cross-tenant sharing or aggregate. For system scheduled report creator use admitted single-tenant service identity; no global unscoped reader.
Effective access = active tenant membership AND report audience policy AND current domain/owner permissions AND authorization for the entire actual data scope of that artifact AND file permission where applicable. Deny by default; explicit revocation wins. Report audience grants are revocable, versioned and audited independently of immutable report content. Role/employee audience union within tenant, scope restrictions intersect; validate grants and actor delegation against actual owner authorities. No inferred Branch permission from Region/City/Warehouse; use stable owner IDs and qualified Branch→location mapping only, otherwise filter unavailable. Existing warehouse assignment and owner permission checks mandatory. Tenant admin can choose permitted audience but cannot elevate their data rights.
Authorize before enumeration, totals, rankings, metadata, generation, publishing, list/count/search, previews, drill-down, downloads and export. A whole artifact is accessible only if all contents (including metadata, hidden rows, caches, attachments and evidence) are authorized. For employee with narrower scope, generate a separate tenant-owned scope-specific payload/artifact on demand or scheduled when justified, never hide rows in a broader workbook or silently filter its original totals. Recheck policy and ACL at publication and each access; revoke blocks future server access, not already downloaded local copies. Report visibility change does not mutate original analytical digest; audit policy version and grant/revoke actor/time. No share via public storage URL.

Source audit: TenantAuthorization and WarehouseStaffScopeService provide membership/domain/explicit warehouse checks, not report-specific audience management. FileOwnerAccessPort only requireCustomerRead/Modify; FileAttachmentService currently CRM_CUSTOMER owner binding, FILES_READ/ATTACH/DETACH with CRM checks, synthetic-only comment. Report owner binding and audience authorization are explicit missing integration contracts; reuse existing File Service/RustFS, no assumption generic report attachment already works. Minimal persisted report instance/access policy only if existing owner/job/file storage cannot support them, decide after inventory; no DDL here. Branch owner mapping not qualified by current aggregate audit.

## 2. Immutable report passport and mutable access policy
Extend existing MicroReportPayload/manifest, not parallel data bank. Required user-facing passport (Dashboard compact header, Metadata full table, PDF first-page compact parameters and metadata appendix as appropriate, React metadata panel):
- identity: tenant ID/display label, report instance ID, report code/name, template version/digest, payload schema/version/digest, generatedAt and analytical actualAsOf separately, creator/service identity where authorized, mode NIGHT/INTRADAY/EVENT/ON_DEMAND as applicable, status and supersedes reference.
- parameters: requested and actual permitted scope (only expose requested IDs to entitled actor; no forbidden scope/count leak), exact period from/to half-open with timezone and calendar version, period code D/W/DEC/M/Q/H/Y, comparison and actual baseline bounds, displayed/required history and coverage, metric codes/method versions, currency and UOM, region/city/branch/location/warehouse/product group/subgroup/SKU filters with stable IDs, historical mapping version where admitted. Each filter explicit SELECTED / ALL_AUTHORIZED / NOT_APPLICABLE / UNAVAILABLE; no ambiguous null or unsupported dimension silently ignored. Reject unsupported selection (BOOKED geography, city/branch unqualified, mixed currency/UOM). ALL_AUTHORIZED binds actual scope snapshot, not future rights expansion.
- analytical: dynamic contract IDs, grouping basis/step/policy/FIXED or DYNAMIC/anchor/membership digest where applicable, actual limits, scan completeness, unit/display scale, locale, comparison semantics, quality/activity/eligibility and reason, warnings.
- evidence: source owner, revision manifest, generation/proof when applicable, exact intervals and coverage/qualified zero, evidence references, artifact digest stored separately from payload digest (avoid self-reference). Retain immutable analytical params and evidence; historical drill-down exact retained evidence or fail closed, LATEST_DATA separate. Current audience policy/version separate mutable owner metadata; do not embed employee allow-list in distributed workbook/PDF. Security/internal identifiers only where needed and authorized, never tokens/credentials. Current audience state not immutable historical report value.

## 3. Tables are mandatory companions, not a new engine
Every material chart/KPI block has corresponding typed table/row accessible from same qualified payload, same scope, asOf, unit, period, precision, grouping and evidence. No independent Excel/PDF/React business arithmetic, no formula-based change of scope or totals. Backend authoritative values/ratios, exact BigDecimal and explicit rendering precision. Show Metric Code + localized Hint. Missing/partial/stale/NA distinct from zero; per-value quality, deterministic sort, visible applied filters and denominator semantics. Excel Tables filter/sort the authorized rows only; a filter does not change published total (label full-scope total vs visible subset; subset recalculation only a new authorized request). Pagination/truncation explicit, no hidden data, no fabricated totals. Additive total reconciles; exact distinct recomputed at target grain; ratios of sums not averages of ratios; incompatible currency/UOM separate. For 500+ rows use D06E.5.1 up to seven rank bands with bounded detail; PDF bounded summary/table plus reference to authorized detail, no promise all rows printed. CSV optional future existing export binding only after admission.
