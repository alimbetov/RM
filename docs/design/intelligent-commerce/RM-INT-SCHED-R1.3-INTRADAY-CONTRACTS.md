## 2. Contract A — real service principal and explicit scope

Decision proposed: reuse real IAM account, membership and enforced RBAC for authorization, with distinct cryptographically authenticated service token and narrow internal adapter. Not an owner impersonation, not raw UUID, not synthetic VerifiedActor, not a new universal administrator. Service token must be issued by approved Keycloak confidential workload client (client_credentials or existing approved workload credential), separate service audience, pinned issuer, expected azp/client ID and exact linked subject. No token accepted with ordinary user API audience; ordinary HTTP decoder must reject service-only tokens. No interactive session or delegated owner access. If issuer cannot issue this shape, remain OFF; do not silently fall back to user tokens. Credentials via approved secret manager, not repository/config literals or job payload. Obtain/refresh token outside DB transaction, bounded timeout; verify expiration at read and persist, no token/body/secret logs. Use actual production JWT decoder validation (signature, issuer, audience, Bearer purpose, exp/nbf), additional service-client/subject restrictions; do not weaken user decoder. Provisioning/rotation and actual issuer configuration require owner/IAM approval; no automatic create account, membership or permission on scheduler startup. Test locally signed JWT is qualification fixture, not deployed identity.

## 3. Contract B — immutable durable outcome / acknowledgement

Decision proposed: one narrow logged PostgreSQL table crm.int_intraday_result, one request/outcome per existing INTRADAY job. Not a second scheduler, report dataset, warehouse, outbox, or File Service artifact. The durable internal consumer INTRADAY_SNAPSHOT_STORE_V1 acknowledges by atomically committing the exact outcome with job COMPLETED. This is storage acknowledgement ONLY; no report/Radar delivery acknowledged. A future approved report consumer uses its own S4/S5 lifecycle with fresh authorization, never assumes job completed means delivered. If the owner requires an external consumer acknowledgement rather than this bounded storage consumer, keep R1.3 blocked until that consumer is admitted. Do not mark COMPLETED on merely computing an in-memory value.

Proposed DDL shape (review actual migration head and deployed DATABASECHANGELOG first; no changeset ID assigned or applied here):
```sql
CREATE TABLE crm.int_intraday_result (
  tenant_id uuid NOT NULL,
  job_id uuid NOT NULL,
  schema_version smallint NOT NULL CHECK (schema_version=1),
  consumer_code varchar(48) NOT NULL
    CHECK (consumer_code='INTRADAY_SNAPSHOT_STORE_V1'),
  service_account_id uuid NOT NULL,
  scope_version bigint NOT NULL CHECK (scope_version>0),
  scope_digest char(64) NOT NULL CHECK (scope_digest ~ '^[0-9a-f]{64}$'),
  request_payload jsonb NOT NULL,
  actual_as_of timestamptz,
  source_revision bigint CHECK (source_revision>=0),
  result_payload jsonb,
  result_digest char(64) CHECK (result_digest ~ '^[0-9a-f]{64}$'),
  acknowledged_at timestamptz,
  PRIMARY KEY (tenant_id,job_id),
  FOREIGN KEY (tenant_id,job_id)
    REFERENCES crm.int_analytics_job_run(tenant_id,job_id),
  CHECK ((acknowledged_at IS NULL AND actual_as_of IS NULL
      AND source_revision IS NULL AND result_payload IS NULL AND result_digest IS NULL)
    OR (acknowledged_at IS NOT NULL AND actual_as_of IS NOT NULL
      AND source_revision IS NOT NULL AND result_payload IS NOT NULL AND result_digest IS NOT NULL))
);
REVOKE ALL ON crm.int_intraday_result FROM PUBLIC;
```
Proposed follow-up constraints/triggers in same approved migration: require parent job_type=INTRADAY; immutable request fields; exactly one null-to-ack transition; immutable acknowledged row; validate matching calendar, slot, day, scope, current claim at write; deferred commit check matching job COMPLETED + exact actual_as_of/source_revision and acknowledged row for every completed INTRADAY, including direct SQL negative tests; no deletion/truncate via runtime grants. Enqueue parent+request same transaction; no orphan parent in admitted execution; existing legacy fixture reserved INTRADAY rows without request are not claimable. Validate existing rows before enforcement, no edit to 0224. FK tenant composite; no cascade. Service account linkage verified by IAM, optionally FK after lifecycle inventory; no user PII in payload. One operational row per slot, <=7/day/pilot tenant, bounded payload proposal <=16 KiB canonical UTF-8 (single metric first, DB/application limit), retention pilot hold/no automatic deletion. Storage capacity and retention owner decision before rollout. Future report staging partition retention is independent; do not retain report data forever here or add partition manager now.

Request fields: version, tenantId, jobId, serviceAccountId, scopeVersion, consumer, metricCode, methodVersion, calendarVersion, zone, businessDay, scheduledSlot, all normalized filters including explicit none. Scope digest over canonical policy fields excluding job ID/slot; request immutable; verify full equality on conflict, adopt winning job ID, never overwrite. Result fields: exact request identity + actualAsOf UTC micros, sourceRevision, [dayStart, actualAsOf) bounds, metricCode, methodVersion, value as exact decimal string or null, unit, currency, quality PARTIAL/MISSING, qualityReason, route L0, generation/proof null. Schema v1 deterministic fixed key order, UTF-8, explicit null, canonical decimal without exponent/trailing zero ambiguity, normalized UUID/UTC microseconds, SHA-256 lower hex computed on canonical bytes, not PostgreSQL jsonb::text or Java object toString. Verify digest on read; no access tokens, PII, raw rows or forecast. No qualified zero from no rows. Bounded internal retrieval keyed tenant/job under current service authorization; latest result chooses current business day/calendar/scope and latest actualAsOf then slot/job tie break; never sum prior rows. No public endpoint until separate approved consumer/read ACL.

Ensure distinct pod claim tests 1/2/4 and uniform config/drain.
- T1 RC: register request + job, compare winner. T2 RC: lock due job, claim fenced token, commit; do not hold locks during token acquisition. T5 RC: job FOR UPDATE exact current type/token/owner/slot/lease, lock IAM actor then workspace SHARE, verify ACTIVE tenant/org, effective calendar, grant, request and current day/slot; nested RR read only one actual snapshot via existing L0. Outer RC rechecks current DB time, latest due slot (if new due while running, discard old candidate and SKIP; do not publish under wrong slot), current authority and lease; persist immutable payload + digest + ack and guarded job COMPLETED in SAME transaction. Ensure exact metadata equality and no ACTIVE pointer/generation/receipt mutation. On any write/fence error rollback BOTH; retry computes a fresh observation only if no prior ack and same current slot remains valid; after committed ack return existing exact payload (no second read/recompute/write). Lost commit response recovered by immutable job+result. Release slot only with durable terminal transition. Explicit skip/blocked reason stored; do not pretend read succeeded.
- Bounded timeout/lease: reuse existing defaults 300s/2 slots, measure actual RC+RR latency; avoid holding job/workspace across token network or rendering. Uncertain process death leaves lease; use DB time; no physical exactly-once assertion. Log tenant/job/slot/token/quality/reason/duration, not payload/credentials. No new dependencies.
