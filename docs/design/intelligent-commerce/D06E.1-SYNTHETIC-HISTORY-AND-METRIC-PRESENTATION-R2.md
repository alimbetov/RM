## 4. Mandatory Metric Code & Hint Presentation Contract
Owner decision: chart titles, series legends and analytical column headers use stable Metric Code; human-readable purpose is a localized Hint, never a replacement for the code. Applies to D06C template manifests, MicroReportPayload, React/ECharts, XLSX, PDF and Radar analytical details. This refines prior generic localized chart label guidance; user-facing Radar business ticket titles remain plain localized language. For same metric comparison series use code plus explicit comparison identifier (e.g. FULFILLED_AMOUNT / CURRENT_12M and FULFILLED_AMOUNT / PREVIOUS_12M), or comparison identifiers alone when metric code is unambiguous in chart title. Include unit/currency, period, actual asOf, scope, quality and coverage; don't imply missing values are zero. Preserve fixed template ranges and chart gaps. Do not truncate codes so they become ambiguous; wrap or adjust trusted layout.
| Format | Metric Code | Hint |
|---|---|---|
| React / ECharts | chart title, series legend, analytical headers | accessible tooltip/info control, keyboard/touch available |
| XLSX / Apache POI | chart title, series legend, table header | cell note/comment or Metadata dictionary accessible without external links |
| PDF | chart title/legend and analytical headers | static adjacent note or compact glossary keyed by code; no hover dependency |
| Radar | analytical detail code | expandable localized explanation; business title remains human-readable |
| REST payload | metricCode and comparisonCode where applicable | hintKey or resolved localized hint; no identity based on translation |
Reuse existing metric definitions and versioned resource bundles; no new localization service, duplicate registry, DSL or per-locale workbook layout. Logical presentation metadata: metricCode, hintKey, unitCode, displayScale, formatCode, registryVersion; final type names after inventory. Example key metric.FULFILLED_AMOUNT.hint. Derived display codes MOM_PCT, YOY_PCT, SMA_3, CV, SHARE_PCT, COVERAGE are presentation examples only; map to existing qualified method codes, retain canonical ratio semantics, convert to percent once, distinguish percentage points. No misleading alias or invented method. Same versioned dictionary and payload across formats; explicit fallback for unavailable locale, validation for unknown metric code. Hint must explain semantic limits (e.g. order amount not revenue, movement not balance).

## Metric Presentation Contract — MPC-1 (owner agreed)
Extend existing metric passport/crosswalk and resource bundles, not a duplicate runtime registry or formatter service. Resolve metricCode, methodVersion, operand/role, presentationVersion, hintKey, actual unit/currency, display precision/rounding/scale, signed/ratio/pp semantics, allowed chart/axis/legend/label, direction semantics, quality/reason and locale into one versioned descriptor used by React/ECharts, XLSX/POI, PDF and Radar analytical detail. The D06E.4 JSON assigns one proposed default profile to each of all 53 registered entries; this is not metric admission. FORECAST_NEXT stays HOLD; unknown owner field/operand/UOM mapping blocks binding.
Exact BigDecimal remains backend authority. COUNT integer, MONEY two decimals and explicit actual currency, fixed K/M scale only per compatible block, quantities use actual UOM precision (proposed max 3 decimal display fallback when unit known), count averages/SD remain decimal, slope uses operand per ordinal period, signed deltas inherit operand precision. Default display-only HALF_UP, normalize rounded negative zero; no rounding before ranking, thresholds, aggregation or reconciliation. Excel numeric values beyond 15 significant digits require explicit precision disclosure and exact evidence representation; no pretending binary floating point equals exact BigDecimal. Excel number format and chart cache correspond to same plotted numeric value; a fixed scale must be applied once and labeled, not mixed with a second axis scale.
Canonical ratios are fractions: 0.125 → 12.5% exactly once, Excel 0.125 with 0.0% format. SHARE_DELTA_PP already 100×share difference: 0.40→0.50 gives +10.0 pp, no percent format. Negative/positive growth signs explicit, zero baseline undefined ratio blank with reason, absolute delta remains when qualified. No fake zero, NaN/infinity, no line across missing intervals, no stale numeric cache. PARTIAL descriptive value may be shown with clear status if admitted; MISSING/NOT_APPLICABLE/STALE/invalid comparison never masquerades as qualified zero/active business finding. Direction colors neutral by default; green/red only when qualified business meaning or explicit increase/decrease legend, never assume rising stock/cancellations is good. Use text/sign/shape as well as color, accessible contrast. Chart titles and table headers Metric Code; Hint localized RU/KK, EN target, PDF visible. Stable series comparison role, axes show actual units/scale; no mixed currency/UOM, no misleading dual axes; choose charts only per DC applicability, labels for compact bars, suppress clutter on dense lines. Same chart/table values, scale, period, quality and scope, filter cannot silently change published denominator.
Template manifest/payload digest bind presentation version and resolved descriptor; localized formatting at display boundary only. Qualification extends existing CC-03/09/10, UAP-02/09, TPL-01/03/04/05: 0.125, -0.084, zero, undefined prior, pp, fractional UOM, count mean, large values, mixed currencies, long codes, locales, missing points and cache parity. No runtime PASS. MOCK-0.1 remains the committed binary catalog; locally discussed MOCK-0.2 formatting is a candidate, not a verified repository update in this pass.
