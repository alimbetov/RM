## 1. Business objective and defaults
Show the entire eligible distribution of a high-cardinality dimension in a single compact report, retaining exact detail via drill-down. Up to five eligible elements: show individually; above five: use at most seven rank groups. Default COUNT_PERCENTILE, step 15% of eligible item count; six nominal 15% bands and residual 10%. Alternative CUMULATIVE_VALUE_SHARE uses 15 percentage-point value bands. Ranking descending by one qualified nonnegative additive metric, one currency/UOM, one scope/period/method; stable canonical scope key ascending as tie-break. Not ABC/XYZ, not a composite score, not new risk classification. No arbitrary user-uploaded grouping expressions. Threshold/step are versioned presentation policy; changing them does not change underlying metrics or business pattern validity.

## 2. Exact deterministic grouping algorithms
Eligible population is authorized, complete at the chosen grain and comparable under the same pinned evidence manifest; no unauthorized row/count/denominator leakage. Rank row_number over value DESC, stable scope key ASC; N is actual eligible item count, not directory size or displayed top-N. Zero-valued qualified items included when eligible; missing/partial rows not substituted with zero; incomplete population cannot claim a full distribution. Distinct metrics excluded from sum grouping unless disjoint identity partition and exact parent reconciliation proven (default reject). Negative values or nonpositive total: COUNT_PERCENTILE can show qualified zero-valued groups for nonnegative measures, but shares unavailable at total zero; CUMULATIVE_VALUE_SHARE unavailable at nonpositive total. Signed metrics use separate qualified contribution views, not this concentration algorithm.
- COUNT_PERCENTILE: for N>5, group j=1..7 uses ranks (ceil(N*min((j-1)*15,100)/100)+1) through ceil(N*min(j*15,100)/100), inclusive. Use exact integer arithmetic, omit empty bands without renumbering stable band IDs G01..G07. For N=500: 1–75,76–150,151–225,226–300,301–375,376–450,451–500. For N=6 or 7 some bands may contain one item; do not fabricate compression. Ties may span bands, stable key decides membership, not a claim of materially different performance.
- CUMULATIVE_VALUE_SHARE: use exact unrounded cumulative value BEFORE each ranked item divided by total. Assign j=min(7, floor(cumulativeBefore*100/(15*total))+1), exact numeric comparisons, boundaries left-inclusive/right-exclusive except final band includes 100% (trailing zero-valued items go to G07). Never split item or force exact 15% sums. A dominant item may cross several nominal bands; omit empty bands, retain original IDs, show actual cumulative bounds and actual group share. The number of items per group varies. N<=5 remains direct mode. Document distinction from COUNT_PERCENTILE and from ABC thresholds.
All members assigned exactly once; sum group counts=N and sum group values=qualified parent value for the selected authorized population. Share ratios use exact group sum/parent total, no renderer arithmetic; rounding only for display, rounded shares may not total exactly 100%. If parent is authorized subset label it explicitly. No hidden OTHER or fabricated residual.

## 3. Historical comparison
FIXED_RANK_GROUPS: membership anchored to explicit qualified baseline period (or explicitly selected reference period); freeze member keys, rank basis, policy and scope digest for the comparison window. Group history sums the same members, not re-ranked rows. New eligible items absent from anchor are shown separately in a labeled NEW/UNASSIGNED reconciliation row/table (not silently assigned to a historical band); if necessary display separate non-band indicator, not eighth rank band. Anchor-only members retain group; missing historical fact is null unless qualified zero. If anchor cohort does not cover target population label cohort-only total, reconcile full total separately with new/unassigned when qualified. No inferred growth on zero or unavailable prior. Authorization changes invalidate comparison or produce explicitly requalified authorized cohort, never expose revoked identities. No future rank leakage in as-of historical claims.
DYNAMIC_RANK_GROUPS: rank independently each period with same method and eligible scope policy; compare rank-band distributions, counts, concentration and shares, not growth of identical SKU cohort. Label membership varies; allow band-to-band share comparison only with qualified complete denominators. Direct/grouped display boundary crossing (N<=5 vs >5) must not imply equivalent series; use explicit comparable band analysis only when both periods use same group policy or abstain. Do not present a dynamic G01 comparison as fixed cohort trend. Display comparison mode, anchor when fixed, population counts and coverage.

Native chart limits/long labels/accessibility qualified; blank unused slots; no demo values, stale cache or hidden unauthorized rows. Metric Code + Hint unchanged. ## 5. Implementation and qualification
Reuse set-based bounded authorized extraction and existing SQL/JDBC window functions (ROW_NUMBER, SUM OVER) or existing deterministic typed mathematical layer after qualification, never SQL per item/period or calculations in renderer. Ranking requires complete eligible population before grouping; top-N pagination cannot substitute full denominator. For very large populations use database-side ranking/aggregation under pinned revision and authorized filters; return at most seven bands plus metadata and bounded details. No assumption of measured performance. Integrate within existing S2/S3/S4 and CC-02/03/04/09/10/12, UAP/TPL/PERF/SEC cases; no new family counts. B5.5 first.
