Four logical banks mean four views of the same evidence (absolute, relative, detected patterns, user information), NOT four physical databases, tables, services or copies of all rows. Keep existing L0/L2/L3 canonical for derived reads. Compute transient relative values in bounded batches; persist only the minimal ticket/evidence and immutable published report state required for replay, audit and lifecycle, reusing existing storage/contracts after inventory. Prefer configuration as typed versioned Java definitions and localized resource bundles, not a generic editable registry UI. No automatic business commands.

## 3. Historical coverage first (T02, T13)
D06D §8 is mandatory. Distinguish (a) source completeness, (b) projection parity, (c) pattern-specific required interval coverage, (d) permission and decision eligibility. A closed period with an existing row or current proof is insufficient for READY. Before allowing qualified historical reads, establish owner-specific completeness evidence for tenant/scope/metric/time interval: source onboarding/import boundaries, expected source streams, committed fact enumeration, missing source ranges, historical dimension attribution, delivery/rebuild revision and closure. Use owner-backed facts/receipts and independent reconciliation; a timestamp, row count, imported history claim or calendar closure alone cannot prove completeness. If no credible source evidence exists, retain PARTIAL/MISSING. Proven zero only where metric semantics and complete source coverage establish zero; pre-creation history is not zero. Do not add a duplicate coverage ledger before inventory proves existing contracts insufficient. Minimum evidence fields: required interval set, covered interval set and reason codes, scope, metric/source, calendar, source/generation/proof revision, method, asOf; persist/reference evidence using existing ownership. 
For NIGHT use 24 closed calendar months, show 12+12; a pattern may require less or more. For INTRADAY compare only qualified equivalent elapsed intervals in tenant calendar (including DST/holidays if relevant to method); exact historical cutoff/availability proof and open-period method admission are not established. Until then only descriptive PARTIAL, no comparative business alert. Current-day cumulative [dayStart, actualAsOf), never sum snapshots. Missing comparator blocks only dependent claim; short independent qualified pattern may still operate. No universal 80% coverage rule. Distinguish required coverage ratio from confidence.

## 4. Bounded dataset and scope contract (T06, T07, T08, T11)
One logical read request: tenant, verified actor or separately admitted service identity, eligible metric codes, authorized scope batch, explicit required calendar periods, comparison mode, calendar/version, bounded page size. Response: stable scope keys and ordered period rows, nullable value, unit/currency, source quality/activity, provenance, coverage reasons, manifest of source/generation/proof and observation time, continuation key and scan completeness. Reuse existing result types where compatible; no new public API mandated. Batch authorization before extraction; stable keyset pagination and bounded transactions. Reuse L3DerivedSeriesService.readPeriods for native set-based extraction across period sets; extend authorized bounded compatible scope batches, no metric×period×scope N+1, no blanket limit increase. Pin revision coordinates across pages or restart affected work on drift; independent snapshots must not be declared one MVCC snapshot. Do not hold a transaction across rendering, file IO or entire tenant night. Validate revision/authorization again before publication.
Enumerate sparse eligible scope from qualified historical facts and existing projections, including previously active now-absent groups; do not generate Cartesian product of all dimensions. Separate geography (tenant/region/city/warehouse when supported) and product group/SKU hierarchies, permit all valid intersections. Use historical membership and location, not today's catalog mapping. City remains blocked until KATO mapping/rollup proven; republican city must not be counted twice as region and city. BOOKED remains without geography until an explicit owner attribution contract; quantities require compatible SKU/UOM; no addition of unlike units. Authorized tenant total may only represent visible subset, labelled accordingly. Exact distinct recomputed at target grain; parent/child totals not assumed additive. 
Use existing revision/dirty/rebuild logic to identify affected scopes and periods, including dependent lookback/comparator windows and ancestors; if affected-set proof unavailable, bounded recompute of whole affected tenant slice is safer than stale results. Night reuses unchanged rows; intraday recalculates current-day data plus dependent claims. Never modify ACTIVE L3 or sum old/new generation. Coverage of evaluated eligible scope set distinct from top-K results; incomplete/budget exhausted explicitly reported.

## 5. Unified metric, label and pattern registry (T03, T04, T05)
One semantic crosswalk over existing MetricRegistry and authorized read enums; no rename/migration merely for labels. Each passport: stable code/version, owner source and basis, aggregation/identity, valid grain, UOM/currency, direction semantics, qualified method and rounding, localization key. Use RU/KK and EN target as D06D; metric/period/unit/comparison/pattern/ticket/quality labels versioned, typed arguments, no arbitrary templates from tenant input. Preserve precise source numeric values; growth ratios format as percent once, pp separate. 
Minimal PatternDefinition fields: code/version, ordered metric codes, eligible scope/grain, exact required interval resolver (target, comparator, optional context, warmup), method reference, threshold policy (absolute and relative materiality when applicable), output information code, evidence requirements. Typed Java registry over existing calculators; no rule language. Start with four candidate patterns; thresholds and exact trend/anomaly methods require qualification, not arbitrary new constants:
| Pilot code (proposed) | Input | Required evidence | Output |
|---|---|---|---|
| P-MOM | eligible booked/fulfilled amount or exact count, separately | adjacent closed comparable periods; positive baseline for ratio | observed increase/decrease, no cause |
| P-YOY | same eligible metric | target month and same prior-year month; noncontiguous allowed by method | annual comparison, not forecast |
| P-TREND | eligible single metric | existing qualified continuous B5.2 window; method-specific min | sustained direction or mixed |
| P-FLOW | fulfilled SKU units, stock-in/out | existing B5.4 equal-duration adjacent periods, same SKU/warehouse/UOM | flow divergence, hypotheses/checks only |
Existing B5.3 anomaly may be exposed only with existing qualified baseline/threshold, not required for first pilot. Wider SHARE/PEER/SEASON/STRUCT and pair combinations after semantic/source qualification, not automatically all 112 families. Distinguish observed direction from business risk; rising quantity can be positive or negative depending on metric. No recognized revenue, gross margin, available stock, debt or customer conclusions unless qualified owners. Use qualified zero transition descriptive code; no divide-by-zero or invented growth. For signed values and ratios require explicit methodology. A small absolute change cannot become high-priority solely because percentage large. No scores presented as probabilities.

## 6. Minimal tickets and lifecycle (T09, T10)
PatternTicket = internal evaluated positive finding, not every candidate/failed check persisted: stable key (tenant, scope, pattern, metric set, comparison episode/period, policy identity), revision-specific evidence digest, observed values, comparison and reason, quality, coverage, method/policy revision. Failed eligibility aggregated into coverage diagnostics, retain detailed reasons on demand; no business ticket. InformationTicket = existing Radar-compatible projection (after gate) with stable situation key, one primary scope, typed label args, references to relevant patterns, current evidence revision, quality/freshness, materiality and optional qualified check. Types RISK, OPPORTUNITY, DATA_QUALITY as logical categories; diagnostics separate from risk counts. No new ticket platform or task duplication. 
Consolidate exact same situation/period within compatible authorized scope; keep most specific affected scope visible. Link parent summary to child evidence without adding overlapping amounts or distinct counts. Do not suppress a child decline because parent grows. Rank with deterministic existing admitted policy and stable tie-break; no weighted scoring system in pilot. Deduplicate same episode across retries/3h updates; new revision supersedes prior occurrence, stable key preserved. New episode criteria explicit in policy before admission. User acknowledgement separate from evidence validity. On missing/rebuild/revoke mark stale/unknown or hide on authorization loss, never resolve solely from missing evidence. Resolve only qualified disproof of condition. Re-evaluate on history backfill; stale worker cannot publish over newer revision. No recommendation when decision blocked; diagnostic check is not commercial action.
