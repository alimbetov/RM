## 1. Решение владельца и границы
Единый банк исторических, пересобранных и текущих агрегатов; окно 24 закрытых месяцев, отображение последних 12 с аналогичными месяцами предыдущего года; универсальные относительные показатели и комбинационные паттерны по всем допустимым глубинам; Pattern Ticket → Information Ticket → Radar и заранее спроектированные отчёты. Дневной цикл каждые 3 часа, ночной с историческим контекстом. Единые labels и фиксированные диапазоны диаграмм. Не подключать Tribuo, ML, LLM, прогнозный движок или отдельный REPORTING/B6/B7. Не менять B4 FREEZE, текущий DAG, MVP, CI, owner contracts и admission gates. B5.5 сохраняет назначение Deterministic Conclusion, Recommendation & Evidence Binding; этот контракт уточняет его целевое применение, не требует завершения всего reporting внутри B5.5. Information Ticket — прежде всего доказательная информация, совет необязателен и только при допустимости; decisionEligibility не повышается автоматически.

## 2. Сверка с baseline
BusinessInterpretationEngine.evaluate принимает 2..12 точек, проверяет единый scope, observedAt, sourceRevision, generation/proof, календарную непрерывность и закрытость; OPEN_PERIOD блокирует интерпретацию, decisionEligibility только BLOCKED. BusinessFactorService.observe использует readMetricWindows для двух периодов и трёх метрик FULFILLED_PRODUCT_UNITS/STOCK_IN/STOCK_OUT, требует SKU и warehouse scope. Не выводить причинность или availability из этих потоков. D06C §2 фиксирует ограничение 12 anchors / 3 metrics и отсутствие доказанного bulk 24M/cutoff. MIC-R2 сохраняет отдельные DataQuality, MetricActivity и DecisionEligibility, числовые shadow candidates не READY. Поэтому 24M и массовое перечисление scope — целевые интеграционные gaps, не существующий API. Не обходить ограничения разбиением на независимые запросы с фиктивным общим snapshot. Сначала inventory и bounded authorized extraction, reuse B4/B5 calculators; без второго расчётного ядра.

## 3. Unified dataset (logical contract, not DDL)
Key: tenant + authorized scope + metric/version + calendar/version + period/grain + currency/UOM + method + source revision manifest. Scope содержит независимые географическую (region → city → warehouse where valid) и номенклатурную (group hierarchy → SKU where eligible) оси; period — отдельная ось. Поддерживать tenant, region, city, warehouse, group на разных глубинах и допустимые cross-axis комбинации. Не строить полный Cartesian product. Перечислять фактически существующие и исторически релевантные scope (включая исчезнувшие в текущем периоде), только metric-applicable и authorized. City и historical group membership требуют квалифицированного mapping; не выдумывать недоступные grain. Tenant isolation applies to extraction, aggregation, cache, tickets, ranking, count, evidence and files.

Logical observation: metricCode, scopeKey, hierarchyVersion, periodStart/end, value nullable, quality, activity, eligibility, unit/currency, source revision/generation/proof, asOf, finality, methodVersion. Dataset manifest pins consistent revision coordinates for all inputs; mixed L0/L3 only via admitted compatibility proof. Rebuilt layer supersedes old active revisions, not additive union. Historical and daily layers never double count overlapping periods. Retain old immutable evidence for audit subject to existing retention/authorization. SUM only for additive metrics; EXACT DISTINCT at target grain via membership/owner source; ratios recomputed from qualified numerator/denominator; AS_OF according to owner policy. No cross-currency/UOM arithmetic, no silent zero, no independent renderer math. Keep canonical values precise, display rounding separate. Prefer existing projections and bounded SQL/Java derived kernels; materialize only measured expensive reusable results, not every combination.

## 4. Time and relative indicators
NIGHT default: 24 consecutive fully closed tenant-calendar months; display 12 current months and matching 12 prior-year months in aligned columns. For each displayed month YoY comparator exists only if qualified. No future/demo values. Missing history explicitly gaps, not zero; distinguish 24-point display coverage from required calculation lookback (e.g. full prior-year trailing windows may need additional history). Two years support year-over-year comparison, not proof of stable seasonality, forecast or causal effect. Other D/W/DEC/Q/H/Y periods use actual calendar boundaries and approved comparisons.
INTRADAY: 03/06/09/12/15/18/21 local nominal slots, actual [dayStart, asOf) accumulation; midnight is close/night. Replace prior cumulative observation, never sum cumulative snapshots. Compare only equal elapsed comparable business intervals with qualified historical cutoff; absent that proof, descriptive PARTIAL only, comparative/anomaly/causal inference HOLD as D06C. Record scheduledAt separately from asOf, timezone/calendar, revision, coverage; delayed/missed runs not fictitious historical snapshots. NIGHT starts on qualified completion, not wall clock alone; reuse history, rebuild dirty affected windows only, atomic publication/fencing per existing owners. Existing EVT event mode independent.

Relative registry (reuse existing definitions, proposed codes): DELTA_ABS = current - baseline; MOM_RATIO / YOY_RATIO = delta / positive baseline; format as percent exactly once; baseline zero/nonpositive per metric policy returns NOT_MEASURABLE for growth (qualified zero→positive may produce separate NEW_ACTIVITY descriptive pattern); no infinity. SHARE = child/compatible parent, only valid additive denominator; SHARE_DELTA_PP = (shareCurrent-sharePrior)*100. Ratio metrics use percentage-point delta where appropriate. MA_3/6/12, CV, trend, TTM/YTD only via qualified existing MIC methods and continuous compatible history; no summation of nonadditive distinct or ratios. Seasonal deviation denotes qualified comparable historical reference, not forecast. Relative thresholds plus absolute materiality, minimum coverage/sample, metric-specific direction and version. Unqualified/unknown suppress interpretation, not evidence of absence.

## 5. Pattern bank and tickets
Versioned registry, typed Java rules, no DSL or arbitrary expressions. Universal candidates: sustained increase/decrease, abrupt change, acceleration/deceleration, reversal, stagnation, YoY divergence, volatility, parent share change, peer deviation, paired metric divergence. Applicability registry whitelists meaningful metric pairs, scope, grain, unit, baseline, minimum history, thresholds, quality and output code; do not evaluate arbitrary metric permutations. Existing B5.1–B5.4 outcomes are evidence, not reimplemented. Illustrative pair fulfilled amount decreases + stock-in increases → investigate flow divergence, NOT proven stock accumulation/stockout. Recognized revenue, gross margin, debt, customer metrics only when corresponding owners and sources are admitted.

PatternTicket logical fields: stable logical key (tenant, scope, metric/pair, pattern code, comparison basis/period, policy identity), revision-specific occurrence/evidence digest, values/baseline/delta/ratio, threshold/method/policy version, quality/activity/eligibility, source refs and observedAt. Stable key excludes render time/revision; recurrence episodes and policy changes explicitly versioned. Same input/version yields same semantic result; canonical ordering and digest. Retry produces no duplicate logical effect. Persist only according to measured need/retention and existing lifecycle. Every applicable eligible scope evaluated or explicitly marked incomplete; track coverage counts and reason codes, never call bounded partial scan complete. Top-K is presentation, not evidence of absence.

InformationTicket groups related patterns by authorized scope, situation type and compatible window, preserves child evidence references and localization of deepest affected nodes. Parent growth must not mask child decline. Consolidation must not sum overlapping parent/child effects or exact distinct counts; no collapse across incomparable currency/grain or restricted scopes. Rank by qualified severity/materiality/freshness with stable tie-break, no uncalibrated probability scores. Ticket payload: titleKey, messageKey, typed args, primary scope, affected authorized scopes, observation/evidence refs, priority, asOf, quality, revision, optional allowed check/action link, report ref. Positive opportunities as well as negative signals. No causal claim unless qualified factor evidence proves it. No recommendation when evidence/eligibility blocks it; diagnostic check may be shown only with explicit limitation. User-facing state and analytic freshness separate: ACTIVE, STALE/UNKNOWN, RESOLVED only by qualified evidence, superseded revisions retained per policy. Missing input, expired policy or ACL loss is not resolution. Re-evaluate current permission before list/count/detail/evidence/download; filter before ranking and aggregation, no leaks via hidden sheets/cache.

## 8. Mandatory temporal coverage & ticket validity contract (owner clarification, 2026-11-26)

Полнота временного диапазона проверяется до формирования математического паттерна и до публикации Information Ticket. 24M — целевой горизонт dataset, а не универсальный минимальный порог для каждого паттерна. Для каждого metric/pattern/version registry явно определяет required target periods, baseline periods, lookback/warmup, grain, continuity, cutoff, minimum qualified observations и допустимость partial coverage. Требования проверяются отдельно для каждого tenant/scope/metric и каждой стороны комбинации; наличие полного tenant-level ряда не доказывает полноту дочернего scope. Количество точек само по себе не доказывает календарную непрерывность, source completeness или сопоставимость.

### 8.1. Coverage evidence
Logical CoverageAssessment (reuse existing MIC types where applicable): expected interval set, qualified interval set, missing/partial/stale/incompatible intervals with reason codes, required vs available count, coverageRatio = qualifiedRequiredCount / expectedRequiredCount (null for undefined/empty requirement), actual first/last covered bounds, target/baseline coverage separately, calendar/scope/method/currency/UOM/revision binding, asOf and assessment policy version. A present row is not necessarily qualified. Report gaps explicitly; never infer zero or interpolate to satisfy eligibility. Qualified zero counts as covered; pre-onboarding/pre-creation periods without authoritative proof are NOT_AVAILABLE, not zero. For paired metrics use aligned intersection of qualified required periods; no independent comparison on incompatible subsets. Missing full interval, incomplete source coverage or incompatible revision cannot be cured by a high coverage percentage.

### 8.2. Validity and publication matrix (logical dispositions, not new physical enums)
| Coverage result | Pattern Ticket | Radar Information Ticket |
|---|---|---|
| All mandatory evidence qualified and comparable | VALID candidate, subject to pattern/materiality and other MIC gates | Eligible for publication only after existing authorization and Radar gates |
| Optional historical context absent, mandatory evidence qualified | VALID for the narrower explicitly declared method; historical context PARTIAL | Allowed only for qualified claim, show limitations; no broader seasonal conclusion |
| Mandatory intervals missing, partial, noncontinuous or insufficient lookback | INSUFFICIENT_HISTORY / INCOMPLETE_COVERAGE; no confirmed pattern | Suppress business claim, recommendation, ranking and economic impact; optional separate data-quality notice |
| Cutoff/calendar/scope/method/revision incompatible | NOT_COMPARABLE / STALE | No new active business claim; prior ticket marked stale/unknown as applicable |
| Current-day OPEN/PARTIAL | Descriptive observed value only, per D06C | Clearly preliminary descriptive information; comparative pattern HOLD until qualified cutoff and open-period methodology admitted |

Validity, source DataQuality, MetricActivity, DecisionEligibility, publication state and user acknowledgement are distinct. A diagnostic notice about missing data is not a business-risk ticket and must not be counted/ranked as one. Do not use percentage coverage as statistical confidence or override a mandatory missing interval by arbitrary score. No provisional recommendation or unsupported causal/forecast claim. A separate qualified pattern with shorter required window may still publish on its own merits, without silently changing the original method. Example: 8 qualified months cannot support a 12-month trend or full 12+12 YoY report; a separately qualified MoM comparison can use two adjacent complete months; a single-month YoY requires its two qualified comparable months and any additional method-specific requirements, not necessarily all 24.

### 8.3. Reassessment and reports
On late events, history import, rebuild, revision change or next 3h/night cycle reassess affected coverage and dependent patterns with existing invalidation/fencing. Previously valid ticket whose evidence becomes incomplete is STALE/UNKNOWN (not RESOLVED); suppress active recommendations and remove it from qualified business-risk counts. Once coverage recovers, re-evaluate deterministically under current authorization and evidence revision; stable logical identity prevents duplicate alerts. If qualified evidence disproves prior condition, resolve per existing lifecycle. Never treat missing data as disappearance of a problem.
Report payload carries per-series/per-point quality and coverage summary, required/available period bounds and localized reason keys (e.g. quality.insufficient_history, quality.incomplete_coverage, quality.not_comparable). Fixed 12+12 charts retain empty slots and show gaps, not zero or connected misleading interpolations; Excel/PDF/React agree. Example notice: «Доступно 8 из 12 необходимых месяцев. Годовая динамика не оценена». Scope and evidence visibility are enforced before all coverage counts and details. No new report template per coverage status.

Test new tenants and newly introduced SKU/groups, 0/1/8/11/12/23/24 available months, one missing interior month, partial month with row present, proven zero, missing comparator, insufficient warmup, incompatible cutoff/calendar/revision, paired-series misalignment, parent complete vs child incomplete, independently valid short-window pattern, late backfill and regression of prior READY evidence. Independently enumerate required calendar intervals and source completeness; assert no false ACTIVE/RESOLVED ticket, no duplicate on recovery, no inappropriate recommendation, accurate localized gaps and cross-format parity. Include tenant isolation and concurrent refresh/invalidations. These are extensions to existing UAP cases, not new family counts or runtime PASS. Concrete per-pattern minimum windows/thresholds require method inventory and qualification; no blanket percentage threshold is approved. Existing MIC, B4 FREEZE, D06C restrictions, separate Radar admission and production HOLD preserved.
