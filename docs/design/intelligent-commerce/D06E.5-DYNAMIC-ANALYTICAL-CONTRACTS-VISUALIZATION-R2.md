## 1. Stable data contract
Reuse one immutable MicroReportPayload. A dynamic block is a typed section of that payload, not a new DTO hierarchy/service per chart. Working names only:
- request context: reportCode/templateVersion, dynamicContractCode/version, tenant/verified actor or admitted service, eligible metric/method version and role, scope keys/filter, period code and actual bounds, comparisonCode, display range, currency/UOM, calendar/policy, asOf mode, bounded page size. Authorization before scope enumeration or totals.
- result manifest: actual asOf, source/generation/proof/revision, authorization scope, calendar and method/policy versions, source and temporal coverage, scanComplete, truncation, immutable digest. Null with reason, never missing=zero.
- typed rows: stable row/scope/series keys; period start/end, metricCode, hintKey, value BigDecimal nullable, unit/currency, quality/reason, evidenceRef; optional target/prior/delta/ratio/share/threshold/role only for admitted contract. No localized string as identity, no arbitrary expressions or SQL.
- series binding: stable key, metricCode, comparisonCode or role, displayScale/format, axis unit, chart binding key, deterministic order and explicit missing behavior. Layout manifest preconfigured, no business formulas in Excel/ECharts/PDF. Actual values remain precise; presentation rounding not source arithmetic.
- interpretation: existing B5.5 qualified outcome, evidence and allowed checks, optional ticket references; no independent narrative generation in renderer. Separate quality, activity, decision eligibility, publication, acknowledgement. Data-quality diagnostics not risk/opportunity counts.
One dataset/read manifest may serve many blocks. Reuse existing authorized read and set-based readPeriods, bounded bulk CC-02; never fetch per chart×metric×scope×period. Compute derived values in existing mathematical layer only. Same qualified payload for React, Excel and PDF; format-specific fallback may be table, never different numbers. Reauthorize and revision-fence before publishing/downloading; no hidden unauthorized data or caches.

## 3. Interpretation rules by chart type
- KPI/sparkline: show metric code, Hint, actual period/asOf, units, comparison basis and coverage; arrow and sign express direction, not automatic business benefit. Never display fake trend for a live-only value.
- Line/paired bar: chronological calendar slots, common aligned units; show gaps, no interpolation or connected gap. Previous period vs prior year distinct comparison codes; no unqualified open-period growth. Monthly default 12 current + 12 prior slots; range selector 3/6/12/24M display only. 24M is not universal lookback or 24 additional comparator months.
- Bar: zero baseline for magnitude, stable sort, no misleading truncated axis. Nonadditive metrics may be ranked but not stacked as total.
- Donut/stack/100% stack: only qualified complete partition with compatible denominator and nonnegative parts; total and denominator visible. Partial scan uses individual bars/table, not whole-circle claim. Do not silently invent OTHER or normalize displayed top-N to 100%.
- Waterfall: parent delta equals sum child deltas in exact arithmetic; independent oracle, reject nonadditive, overlap, currency/UOM mismatch or incomplete population. No balancing plug or causal label.
- Pareto: complete denominator, descending value and stable key, cumulative share in backend, final 100% only on complete population; no ABC classification before W3.
- Heatmap: independent axes, stable rows/columns, sparse qualified cells, unknown/partial/NA distinct from zero, fixed documented symmetric relative scale and clipping legend. Positive/negative direction not automatically good/bad. City unavailable until qualified.
- Scatter/bubble: same scope and period for all axes; qualified x/y/size; size encoded by area not radius, nonnegative size, axis units, declared deterministic quadrant boundary if used. No recommendations merely from quadrant. If bubble unsupported in XLSX/PDF use equivalent scatter/table with size column.
- Anomaly band: preceding baseline excludes target, thresholds from admitted B5.3 policy; not confidence interval or probability; SD=0 standardized deviation null; high CV/zero baseline abstention. Do not draw gap as zero.
- Combined evidence: separate panels for incompatible units; no dual-axis chart that suggests numerical comparability, no correlation/causation claim from co-movement. B5.4 uses exactly three roles and two adjacent equal-duration periods.
- All: no 3D, accessible contrast, text/sign/icon redundant with color, stable code not translated, localized Hint RU/KK and EN target, English fixture Region/City, PDF static explanatory legend; bounded rows and fixed chart bindings. Layout must remain stable with 0/1/many rows, long labels and missing history. Unknown metric/method binding fails closed. No new rendering dependencies until admission.

## Final P0 safeguards
FULL_DISTRIBUTION uses the entire authorized metric-applicable expected population, including eligible proven-zero rows, before materiality or top-N. Establish scope and interval completeness independently; missing/partial expected rows or budget exhaustion block complete-distribution claims, not silently shrink the denominator. MATERIAL_FINDINGS evaluates all required applicable scopes and applies admitted materiality only to qualified findings/ranking/ticket selection; it never supplies the denominator of FULL_DISTRIBUTION. Both reuse compatible evidence. These are logical selection purposes, not new engines or public enums.

Business scope identity (tenant plus stable authorized business scope keys, independent geography/product axes) alone anchors existing business PatternTicket/InformationTicket keys. G01–G07, grouping policy, metric, anchor, comparison mode and membership digest identify presentation groups only. Re-ranking or changing layout cannot create, resolve, suppress or re-key a business ticket. A future concentration-change pattern, if independently admitted, is keyed to the real business population and method, never the mutable band. No new pattern is admitted here.

Default HISTORICAL_EVIDENCE drill-down must reproduce the published report's exact authorized scope, metric/method, period/asOf, payload digest, generation/proof/source revision manifest (or owner-source evidence), and grouping policy/membership digest where applicable. Reauthorize every request against current permissions, verify the complete historical result and detail totals or reject; retained exact details or provably reproducible pinned evidence may be used. A revision number/digest alone is not a historical snapshot. If evidence expired, cannot be reconstructed, membership mismatches or permissions no longer cover the original scope, fail closed with localized unavailable/forbidden reason; no substitution of current facts, no silent narrower denominator. Offer explicit LATEST_DATA as a new authorized query/payload with new asOf and revision, clearly not historical drill-down. Do not expose revoked detail or counts; no mandatory new storage or indefinite generation retention. Paginate with pinned manifest, fail on drift. Previously downloaded files cannot be remotely revoked; future server reads/downloads remain subject to existing ACL.
