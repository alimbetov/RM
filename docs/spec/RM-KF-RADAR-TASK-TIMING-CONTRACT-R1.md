## 1. Single authority
TASKS owns read authorization, source evidence, timing facts, classification and query. One logical Task Timing Engine (not another module/microservice). Proposed TaskTimingQuery constructs one reusable classified SQL relation; original OverdueSignalPage and TaskCalendarPage are projections. Shared policy TASK_TIMELINESS_V1. PostgreSQL SQL is authoritative for classification/direction and exact duration; Java maps typed fields, validates shape, computes display rounding only; independent Java evaluator is TEST ORACLE ONLY, not a second runtime classifier. H2 uses same CASE/policy fragment with a narrow exact-duration dialect adapter if necessary; prove parity. No stored SQL function/view migration, new table/index, cache, event bus, background worker or write path. R0.1 can implement shared timing facts needed by its own authorized read contract; reminder descriptor/localization/timers R0.2 only after separate admission. No general rule engine.

Pipeline: authorized candidates -> source evidence -> exact time facts -> single classified relation -> predicates -> keyset -> LIMIT+1 -> immutable DTO. For overdue-only query optimize away completion history only if equivalence proved against shared relation; do not independently reimplement timing rules. No fetch-all, no pre-limit truncation of candidates, no application postfilter affecting membership, no extra per-task reads.

## 2. Evidence and precision
Sources crm.task_item (tenant_id,id,assignee_user_id,created_by,status,created_at,due_at,row_version) and crm.task_event (tenant_id,task_id,new_version,previous_version,action_code,from_state,to_state,occurred_at,previous_due_at,next_due_at); join by composite tenant+task. One committed statement. TASK stores completion event and terminal due; no terminal reschedule. Completion evidence structurally VALID only if exactly one COMPLETED action with IN_PROGRESS->COMPLETED, previous_version=new_version-1, event version = current row version for COMPLETED or current-1 for ARCHIVED. ARCHIVED additionally requires exactly one matching COMPLETED->ARCHIVED event at current version with proper previous version. Reject duplicate/conflicting terminal evidence. completedAt >= createdAt required; completedAt > evaluatedAt yields AFTER_CUTOFF (concurrent commit or skew), not corruption by itself. Missing/invalid/after-cutoff => UNKNOWN timing and refresh, not a fabricated date or green. Completion timestamp = recorded event, not updated_at, archive timestamp, CRM closure or commit wall time. A valid completion timestamp remains usable for COMPLETED date basis even if due is absent (timeliness UNKNOWN). Terminal state never treated as active overdue.

Original deadline: verify contiguous event versions 0..current row version with CREATED at 0 (previous_version/from_state null, to_state OPEN), previous_version chain and state continuity; DUE_DATE_CHANGED has same permitted state, nonnull next_due_at, null-safe continuity of old/new deadlines and last next_due_at=current due. If no changes and complete canonical history, original=current. Otherwise first valid change.previous_due_at, including null (KNOWN_NO_DEADLINE). Incomplete/inconsistent chain => UNKNOWN original evidence; no invented deadline. deadlineChanged tri-state TRUE if valid change observed, FALSE only if complete proof none, UNKNOWN otherwise. Original outcome independent of effective outcome: ON_TIME/LATE/NOT_COMPLETED/NO_DEADLINE/UNKNOWN. Never conceal original lateness under effective green; no employee KPI inferred. Event versions, not clock ordering, identify lifecycle order. No historical backfill.

Capture trusted Clock.instant() once after IAM admission, truncate to microseconds; bind same cutoff to every SQL expression. evaluatedAt is evaluation time, not DB commit watermark or historical snapshot. PostgreSQL candidate exact signed NUMERIC microseconds via EXTRACT(EPOCH FROM (later-earlier))*1000000; verify precision, negative fractions and supported date bounds on actual PG17. No date_part/double. H2 exact integer primitive with checked range or split calculation; no assumption of parity. Invalid/overflowing input fails closed, explicit evidence error/UNKNOWN as appropriate. For threshold use exact arithmetic 2*elapsed<=planned, not rounded percentages. Percent signed saved/planned, only positive plan; scale 2 HALF_UP at display. No floating point or truncation before classification.

## 3. One ordered decision table
Lifecycle stays separate from TaskTimeliness. First applicable branch wins:
| Branch | Timing class | Direction / magnitude |
|---|---|---|
| CANCELLED | CANCELLED | NONE / absent |
| COMPLETED or ARCHIVED, invalid completion evidence or missing deadline | UNKNOWN | NONE / absent |
| valid completion after effective due | COMPLETED_LATE | LATE / completedAt-due |
| valid completion, plan>0, elapsed>=0, 2*elapsed<=plan | EARLY_50 | EARLY / due-completedAt |
| remaining valid completion by due | ON_TIME | EARLY if before due; EXACT_COMPLETION if equal |
| QUEUED | QUEUED | NONE / absent |
| OPEN/IN_PROGRESS/BLOCKED, no due | UNSCHEDULED (NO_DEADLINE) | NONE |
| OPEN/IN_PROGRESS/BLOCKED, no assignee | UNSCHEDULED (NO_ASSIGNEE) | NONE |
| eligible active due<evaluatedAt | OVERDUE | OVERDUE / evaluatedAt-due |
| eligible active due=evaluatedAt | DUE_SOON | DUE_NOW / zero |
| eligible active 0<due-evaluatedAt<=24h | DUE_SOON | REMAINING / due-evaluatedAt |
| eligible active due-evaluatedAt>24h | ACTIVE | REMAINING / due-evaluatedAt |
| unsupported/inconsistent source | UNKNOWN | NONE |

planned=due-createdAt; elapsed=completedAt-createdAt. Nonpositive plan never EARLY_50; valid comparison still ON_TIME/LATE. Overdue severity separately ATTENTION <24h, HIGH [24h,72h), CRITICAL >=72h; exact magnitude. Compatibility overdueSeconds floors positive micros, including 0 seconds for 1 microsecond overdue. No persisted classification. Colors solely by timing class: EARLY_50 dark green, ON_TIME green, COMPLETED_LATE orange, OVERDUE red, DUE_SOON yellow, ACTIVE blue, neutral gray for remaining classes. No palette in DB. Original-deadline warning independent, not second classifier.

R0.2 maps direction to text code and formats exact magnitude (no additional timestamp subtraction), largest applicable unit floor: >=86400s DAY, >=3600s HOUR, >=60s MINUTE, positive below minute LESS_THAN_MINUTE. Zero only equality branches. Examples 72h -> Осталось 3 дн.; 71h59m -> Осталось 2 дн. (compact whole units, exact due in detail); 1 microsecond late -> Просрочено менее чем на 1 мин.; due equality -> Срок наступил (yellow); completion equality -> Выполнено точно в срок (green). EARLY_50 and EARLY_BY same historical magnitude; ON_TIME can be early by <50%. No timer on completed/archived. Preserve localization RU/KK/EN and accessibility; local text not business predicate.

## 5. Admission, filtering and pagination
Regular Spring transaction through proxy; requireForCommand MANDATORY (actor/workspace row fence) with TASK_READ, VerifiedActor.userId() at admission (expiry); proposed recheck userId before return for long query. Never readOnly=true with PG FOR SHARE, no new task row locks or cached permission. Scope tenant plus creator OR current assignee; no manager/OWNER/global-admin implicit broad grant; current RBAC and existing actor/member/workspace lock protocol must be qualified on actual implementation SHA. Validate cursor/range/enum/limit before reading business rows, fail closed. Concurrent changes return coherent committed statement evidence, not reconstructed mixed timestamps.

Filters: perspective ALL_VISIBLE/MINE_CREATED/MINE_ASSIGNED; state set default all except ARCHIVED; optional timeliness set; dateBasis DUE/COMPLETED; range [from,to) or explicit UNDATED mode (DUE only, no range). AND across categories, OR within set. Explicit empty set rejected; absent means documented default. Original outcome/change filters deferred (display only) until separately qualified; no localized text filter. COMPLETED date basis uses valid completion date even if due missing. DUE/UNDATED can show UNKNOWN. Range required for dated views; absent list range normalized to current month using trusted cutoff and allowed IANA zone, echo appliedFilter. Max 93 local dates. UI inclusive last day converted to exclusive next local day; use atStartOfDay(zone) for DST, not 24h day math. Calendar navigation separate from record pagination.

Order selected date ASC,id ASC; undated id ASC. limit 1..100 (UI 20/50/100), SQL limit+1; hasMore and nextCursor only when extra row. No COUNT or OFFSET requirement. Cursor bound to tenant, actor, canonical filters, date range, date basis, zone, sort, size and last key; reject mismatch, reset on changes. Each page reauthorizes and uses fresh evaluatedAt; live classification/edits can move records across page boundaries, no frozen-snapshot/complete export guarantee. Static fixture exact traversal. UI must indicate incomplete calendar, never invent counts or apparently complete empty days. Optional original filters not implemented implicitly.

## 6. Presentation refresh (R0.2/G2 only)
One page-level timer for active visible rows; monotonic elapsed anchored to server evaluatedAt at receipt, not user wall-clock; network delay means approximate display. Refresh coalesced on focus, explicit change, proposed 60s freshness and deadline/24h transition. At stale or boundary, show pending refresh and previous authoritative color/status; never show a confirmed red overdue label beside server-green/yellow/blue state, or locally reorder/refilter membership. If local estimate crosses a classification boundary, show «Срок уточняется» / pending indicator until fresh response, not a contradictory confirmed countdown. Ignore out-of-order responses by request generation/tenant/filter identity; atomically replace list, text and colors from same page. Do not compare row versions across different tasks as global watermark. On 401/403 or tenant switch clear tasks/cursors and cancel/ignore prior in-flight work; transient network error shows stale timestamp and retry, no fake empty. Hidden view stops timer, no persisted browser tenant cache. No background reminders/scheduler/provider sends. Color+label accessible; calendar markers do not imply duration; same descriptor on list/agenda/calendar.
