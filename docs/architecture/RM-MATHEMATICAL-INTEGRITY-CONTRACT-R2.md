# MIC-R2 — Derived Metrics and Rolling Window Foundation

Owner approved implementation start 2026-11-26. B4.5E; builds on MIC-R1, not a replacement. Production HOLD. Existing CI and mandatory qualification remain unchanged; expansion of tests deferred at owner request.

Internal pure DerivedMetricEngine consumes already authorized, qualified target-grain period values. No direct user/HTTP access, no activation or forecast claim. All seven PeriodResolver codes D/W/DEC/M/Q/H/Y; closed calendar windows, default 3, bounded 2..120. Scope must match tenant, generation, metric/version, dimension, authorization scope, currency/UOM, calendar and source revision. Caller must prove point-in-time provenance; observedAt alone cannot prove no future leakage. Missing or unqualified periods return no value, qualified zero is preserved. Duplicate, incompatible, open/future inputs rejected. DECIMAL128 output. AVG/SMA equal within selected fixed window; change and growth compare last two periods (within complete window); growth/CV ratios not percentages; nonpositive denominator not measurable; TREND is OLS slope per period ordinal; STDDEV_POP uses population denominator. MIN/MAX supported.

Remaining: integrate typed metric registry and authorized L2/L3 series producer; native PostgreSQL window calculations and parity, exact order/line/SKU rollups, revision-aware invalidation for affected windows, point-in-time source availability and historical authorization, EMA and forecast baselines after methodology approval. Do not materialize every dimensional combination. No new tests or test weakening in this change. No READY from unqualified source results; engine's READY means mathematical inputs passed local checks, not proof of authorization or production admission.

Exact orders use membership union; SKU uses distinct identity; amounts and quantity never join membership. Explicit warehouse filter is not actor authorization: internal only. ## B4.5E.7 — numerical candidates
EMA uses alpha=2/(window+1), initialized at first observed value in the finite window; FORECAST_NEXT is SMA naive baseline, not a trained or qualified forecast. Native PostgreSQL numeric window candidate calculator receives bound, calendar-ordered values after source parity; returns final window values for comparison with Java, not authoritative results. PostgreSQL numeric division precision differs from DECIMAL128; tolerance/rounding contract and independent parity qualification are open. Batch across multiple dimensional series, feature availability as-of, exact line memberships and full registry unification remain open.

## B4.5E.7B — batch and exact identity foundation
Native PostgreSQL batch calculator partitions bound numerical inputs by series key, capped at 1000 series / 12000 points, each 2..120 points. This is a numerical batch kernel, not yet a batch authorization or L3 extraction API. Exact line counts use matching L2 contributions within selected L3 cells and period; no additive join. L3 line membership persistence not implemented. Shadow provider enforces Java/SQL candidate parity (v1 exact for min/max/change, relative 1e-14 or absolute 1e-18 for other SQL operators; EMA excluded). Tolerance is a candidate engineering policy pending workload qualification, not a rounding standard. Historical backtesting remains prohibited until immutable availability evidence exists. Current revision and observation timestamp cannot reconstruct past knowledge. No tests changed.

## B4.5E.7C — set-based period extraction and PostgreSQL EMA
Single bound SQL statement extracts the complete requested period set for one metric/dimensional filter; no per-period query. Requested calendar rows drive left joins, preserving missing/stale observations. Exact identities are grouped by target period, additive sums remain independent of membership. Multiple dimensional filters in a single extraction remain open. Recursive numeric EMA uses the finite-window seed and alpha=2/(n+1), now included in parity checks. PostgreSQL precision and workload remain unqualified; no tests changed.

No backfill, no promotion of historical training or inference, no public reads. Feature payload is internal candidate evidence, not authoritative admission. Trusted post-commit observer, writer, payload validation, privileges, historical evidence completeness and backtesting remain open. No tests modified.
