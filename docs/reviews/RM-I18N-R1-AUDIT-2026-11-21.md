# RM-I18N-R1 — аудит трёхъязычности ТЗ и текущей реализации

**Дата проверки:** 2026-11-21. **Ветка:** `feat/rm-kms-r1-implementation`.
**Языки продукта:** казахский (kk), русский (ru), английский (en).
**Метод:** статический аудит кода, наличия ресурсов и утверждённых/предложенных ТЗ. Это **не** browser E2E и не доказательство полного перевода.

## Краткий вывод

**Трёхъязычность архитектурно возможна без отдельных таблиц или партиций на язык. Текущая реализация — PARTIAL, продуктовая готовность — HOLD.**
Техническая поддержка полей КАТО `name_kk`, `name_ru`, `name_en` существует; `name_en` содержит транслитерацию `NameRus`, **не официальный английский перевод**.
В модульном ТЗ отсутствует единый обязательный i18n-контракт API, локализации UI/ошибок, переводимых tenant-справочников, языковых fallback-правил и тестов.

| GEO выборка | `KatoTerritoryDirectory` возвращает все имена и технический код; не принимает Locale | PARTIAL: локализация отображения остаётся на потребителе |
| GEO исходный набор | `kato-data.json` содержит 100 записей и поля NameKaz/NameRus; NameEng добавлен миграцией | PARTIAL: охват Казахстана не полный |
| IAM | `UserAccountEntity` не содержит `preferred_locale` / отдельного профиля локали | GAP |
| Глобальные ресурсы | В исходном дереве нет `messages_kk.properties`, `messages_ru.properties`, `messages_en.properties` или аналогичных i18n resources | GAP |

## Findings по критичности

### P0 — принять до реализации следующих модулей

1. **I18N-01: единый API Locale contract**: только `kk`, `ru`, `en`, валидировать `Accept-Language`, fallback по стандарту продукта. Ошибки и служебные тексты должны иметь стабильный `errorCode` независимо от языка.
2. **I18N-02: английская транслитерация КАТО ≠ перевод**: обозначить `name_en` как Romanized display, не отправлять её в юридические документы как официальный English label.
3. **I18N-03: контент организаций**: отдельные `*_i18n` таблицы для переводимых полей каталога/категорий/услуг, PK/unique по `(tenant_id, entity_id, locale)`, FK по tenant, изоляция по tenant.
4. **I18N-04: шаблоны рассылок**: локаль получателя, версия языка и отсутствие автоматического fallback на неутверждённый текст; согласие `consent_email` независимо от языка.

### P1 — обязателен до production UI и отчётности

5. **I18N-05: immutable snapshots**: язык и версия переводимой позиции фиксируются при подтверждении сметы/заказа, генерируемый PDF отдельно фиксирует свою локаль и неизменяемый template revision.
6. **I18N-06: предпочтение языка**: глобальный `preferred_locale` на user profile или preference, необязательное per-tenant override; не путать с гражданством и регионом.
7. **I18N-07: locale QA**: RU/KK/EN API/error/document/export tests, UTF-8, Kazakh chars (ә ғ қ ң ө ұ ү һ і), fallback, HTML escaping, CSV/XLSX, font glyph support.
8. **I18N-08: privacy**: не автоматически переводить PII/free text; локализация UI не должна включать расшифровку по одному лишь языку.

## Рекомендация

Создать единый [RM-I18N-R1](../spec/RM-I18N-R1.md) и включить его в критерии приёмки каждого домена. Не партиционировать физические таблицы по языку; lookup справочников с учётом locale через обычные индексы/три поля для маленького КАТО, и отдельные module-owned translation tables для контента организаций.

**Итог:** ТЗ/схема трёх языков добавляется в проект; фактическая реализация языковых API, DTO, ресурсов, UI и переводов ещё не проведена и не квалифицирована.

## Дополнение к аудиту — I18N-R1.0A (2026-11-21)

По продуктовому решению добавлен **четвёртый язык `zh-Hans` (简体中文)**. Первоначальный аудит охватывал только `kk/ru/en`, поэтому выводы `PARTIAL/HOLD` остаются; поддержка китайского **пока отсутствует в коде**.

Дополнительные обязательные проверки: `locale VARCHAR(12)` вместо `VARCHAR(2)`, BCP-47 нормализация `zh-CN`/ `zh-SG`, отсутствие несанкционированного fallback для `zh-Hant`, китайские переводы CATALOG и утверждённые MARKETING/legal версии, Unicode/CJK PDF и файлы. Текущий КАТО не содержит китайских названий; `name_en` является только транслитерацией русского. Полное ТЗ: [RM-I18N-R1](../spec/RM-I18N-R1.md).
