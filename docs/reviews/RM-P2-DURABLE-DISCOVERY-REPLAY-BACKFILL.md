## Commit-safe discovery and backfill
Select committed facts using tenant-scoped anti-join to consumer receipts; no irreversible timestamp, UUID, sequence watermark. Lock consumer identity row before selection and use one transaction per fact. Different tenants/consumer identities can execute independently. Same consumer workers serialize, not compete for a shared global lock. Verify canonical fact against immutable owner source through existing MANDATORY appender before delivery, preserve V1/V2 and fail closed on unknown failures. Only allowlisted immutable admission failures become durable rejected receipts, in a fresh transaction after rollback; transient SQL, deadlock or handler failures leave no receipt and propagate. Same principle for backfill, which records INSERTED/VERIFIED/CONFLICT/INVALID. Subsequent scans exclude receipted keys; a new run can re-examine issues without editing historical evidence. Backfill never synthesizes business events or alters stock/order sources.
Run scope is immutable (tenant, run ID, owner, kind, half-open UTC occurred_at range). Range <=31 days, batch <=500, 30s transaction timeout per unit. Bounded time window is not a frozen source snapshot; late commits within that window can change coverage. Repeat scan without advancing a permanent watermark. Coverage query evaluates source/fact/receipt correspondence in one SQL statement snapshot; reports observedAt, counts of missing/unprocessed/rejected/orphan facts/mismatched receipts/orphan receipts. No automatic READY from a prior observation; P3 rebuild requires fresh proof and catch-up. Existing invalid source or digest conflict prevents complete coverage; no destructive repair.
